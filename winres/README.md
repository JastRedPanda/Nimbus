# winres - ресурсы Windows-сборки

Здесь лежат исходники того, что раньше было одним нередактируемым бинарником
`nimbus.syso` в корне репозитория. Теперь корневой файл называется
`nimbus_windows_amd64.syso`, он по-прежнему закоммичен (чтобы обычный
`go build` работал без инструментов и без сети), но его можно пересобрать одной
командой.

## Как пересобрать

```sh
make resource         # сгенерировать ../nimbus_windows_amd64.syso
make resource-check   # прочитать его обратно и проверить
```

`make resource` берёт версию из `git describe --tags --abbrev=0` - той же
переменной `VERSION`, что и остальной Makefile, и того же значения, которое
`-ldflags` кладёт в `internal/build.Version`. Пересборка детерминированная: при
тех же входных данных получается побайтово тот же файл, поэтому лишнего diff в
git не появляется.

Перезапускать нужно после правки:

- `nimbus.exe.manifest` - манифест приложения,
- `versioninfo.json` - строки для вкладки «Подробно» в свойствах `.exe`,
- `../nimbusicon.ico` - иконка.

И **перед выпуском релиза**, иначе версия в свойствах `.exe` останется от
прошлого тега. Ничто не пересобирает `.syso` автоматически: файл под контролем
версий, и релизная сборка не должна молча зависеть от сети.

## Что попадает в .syso

| Тип | ID | Что это |
| --- | -- | --- |
| `RT_ICON` (3) | 2..5 | кадры из `nimbusicon.ico` (256, 48, 32, 16 px) |
| `RT_GROUP_ICON` (14) | 1 | то, что резолвит `LoadIcon(hInst, MAKEINTRESOURCE(1))` в `internal/ui` |
| `RT_VERSION` (16) | 1 | `VS_VERSIONINFO` - вкладка «Подробно» и колонка «Описание» в диспетчере задач |
| `RT_MANIFEST` (24) | 1 | `CREATEPROCESS_MANIFEST_RESOURCE_ID` - манифест процесса |

ID здесь не декоративные. Манифест читается только под ID 1, а иконка окна
берётся `LoadIcon(..., MAKEINTRESOURCE(1))`, так что группа иконок обязана быть
единицей. `make resource-check` проверяет именно это - на Linux, без Windows.

## Почему не готовый инструмент

- **windres** (binutils) требует установленного кросс-тулчейна mingw-w64,
  то есть C-тулчейна в проекте, который специально собирается с
  `CGO_ENABLED=0`. На машине разработчика его нет.
- **rsrc** (`github.com/akavel/rsrc`) - чистый Go, работает где угодно, но
  умеет только иконку и манифест: VERSIONINFO в нём нет вообще. Именно он
  сделал старый `nimbus.syso`.
- **goversioninfo** (`github.com/josephspurrier/goversioninfo`) - чистый Go и
  умеет всё три вещи, но его CLI раздаёт ID в фиксированном порядке: если есть
  манифест, группа иконок уезжает на ID 2, и `LoadIcon(MAKEINTRESOURCE(1))`
  вернёт NULL. Плюс с v1.7.0 он дополнительно кладёт вторую копию иконки под
  `IDI_APPLICATION`, а для нашего 279-килобайтного `.ico` это +279 КБ впустую.

Поэтому `main.go` использует goversioninfo и rsrc как библиотеки, а раздачу ID
делает сам. Чистый Go, без cgo и без Windows.

## Отдельный go.mod

`winres/` - самостоятельный модуль. Это сделано намеренно: `go build ./...` и
`go mod tidy` в родительском каталоге пропускают любое поддерево со своим
`go.mod`, поэтому goversioninfo и rsrc не попадают в граф зависимостей
приложения и в `THIRD-PARTY-LICENSES`. Побочный эффект - рецепты в Makefile
делают `cd winres`, а не `go run ./winres`.

## Ограничение по архитектуре

Имя `nimbus_windows_amd64.syso` - это build-constraint, а не украшение. Файл
`*.syso` без суффикса раздаётся всем целям подряд, а COFF-объект внутри собран
под amd64.

Что именно было сломано у старого `nimbus.syso` - если по-честному: `go list -f
'{{.SysoFiles}}'` выдавал его и под `GOOS=linux`, `go tool pack` клал его в
архив пакета, и `cmd/link` разбирал COFF (он смотрит на magic объекта, а не на
целевую ОС). Но в ELF байты ресурсов не попадали: секцию `.rsrc` пишет только
PE-бэкенд линковщика, поэтому символ отбрасывался как недостижимый. Замерено:
Linux-бинарник с этим файлом и без него совпадает побайтово. Реальная поломка,
которую снимает переименование, - это передача amd64-объекта в сборку под
windows/386 или windows/arm64.

Сейчас:

```
GOOS=linux            go list -f '{{.SysoFiles}}' .  ->  []
GOOS=windows GOARCH=amd64                            ->  [nimbus_windows_amd64.syso]
GOOS=windows GOARCH=386                              ->  []
GOOS=windows GOARCH=arm64                            ->  []
```

Для windows/arm64 ресурсов не будет. Если он когда-нибудь понадобится,
сгенерируйте второй файл:

```sh
cd winres && go run . -version 1.0.15 -arch arm64 -out ../nimbus_windows_arm64.syso
```

## Проверка чужого .exe

`-dump` понимает и объектный файл, и уже слинкованный `.exe`, так что можно
проверить конечный бинарник, не заходя в Windows:

```sh
cd winres && go run . -dump ../build/nimbus.exe
```
